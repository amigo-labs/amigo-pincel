# UI language (English and German)

## Context

Pincel's UI ships in English and German. Every user-visible string comes from a typed dictionary: English defines the keys, German is typed against them, so a missing translation fails the type check. The first launch follows the browser language; a choice made on the start screen or under View ▸ Language is stored and wins from then on. Document content — layer, tag and slice names, file formats — is never translated.

Already decided: "Own DE/EN dictionary", no i18n dependency (Decision Log 2026-10-12). This spec records the behavior as built on 2026-10-29.

## Scope

### In scope

- English and German UI strings for the shell and both editors
- Initial language from the browser; the document's `lang` attribute
- Language switch on the start screen and under View ▸ Language in both editors; immediate effect, persistence
- Desktop native menu following the language
- Document content left untranslated

### Out of scope

- Further languages and community translation — because it is the planned `more-languages` spec.
- Locale-aware number and date formatting beyond what the browser does — because no such behavior exists today.
- Right-to-left layouts — because neither shipped language needs them.
- Translating the website — because `website` owns it.

## Acceptance criteria

- [ ] AC-01 (event): When the app starts for the first time in a browser whose preferred language is any German variant (`de`, `de-DE`, `de-AT`, …), then the UI is German and the page's `lang` attribute is `de`.
- [ ] AC-02 (event): When the app starts for the first time in a browser whose preferred languages contain no German or English variant, then the UI is English and the page's `lang` attribute is `en`.
- [ ] AC-03 (event): When the user picks a language in the start screen's Language selector, then the start screen switches to that language at once, without a reload.
- [ ] AC-04 (event): When the user picks Deutsch or English under View ▸ Language in either editor, then menus, panels, tool labels and buttons switch to that language at once, and the submenu marks the active language as checked.
- [ ] AC-05 (event): When the user has chosen a language and reloads the app, then the chosen language is active, even if the browser asks for the other one.
- [ ] AC-06 (event): When the user switches the language while a document is open, then the document, its unsaved state and its undo history are unchanged.
- [ ] AC-07 (always): Every UI message that exists in English has a German translation; a missing German key fails the type check.
- [ ] AC-08 (always): Document content is never translated: layer, tag and slice names, file names and format names stay exactly as stored, in either language (a new layer is named "Layer N" in German too).
- [ ] AC-09 (always): Each language is labelled in its own language in the pickers ("English", "Deutsch").
- [ ] AC-10 (state, manual: needs the macOS desktop app): While running as the macOS desktop app, the native menu bar is rebuilt in the active language whenever it changes, and at startup.
- [ ] AC-11 (error): If the stored language cannot be read (IndexedDB unavailable or failing), then the browser language is used and switching still works for the session.

## Technical notes

Hints, not contracts — paths drift; grep for the names.

- `ui/src/lib/i18n/index.svelte.ts`: `type Locale = 'en' | 'de'`, `LOCALES = [{ id: 'en', label: 'English' }, { id: 'de', label: 'Deutsch' }]`, `LANGUAGE_PREF = 'language'`, `browserLocale()` (first `navigator.languages` entry whose base is `de` or `en`, else `'en'`), `applyLocale()` (sets `document.documentElement.lang`), `t(key, params)` with `{name}` placeholders (unknown placeholders stay as written), `isMessageKey()`, `isLocale()`.
- `ui/src/lib/i18n/locale.ts`: `initLocale()` (restore pref, called from `App.svelte` on mount), `setLocale()` (apply, persist to the IndexedDB `prefs` store, `invoke('set_menu_language', { lang })` under Tauri), `languageMenu()` (View ▸ Language submenu, `checked` entries).
- Dictionaries: `ui/src/lib/i18n/en.ts` (`export const en = { … }`, `MessageKey`), `ui/src/lib/i18n/de.ts` (`export const de: Record<MessageKey, string>`).
- Tauri side: `set_menu_language` in `src-tauri/src/main.rs`.
- Default layer names are English and never pass through `t()`: Pixel mode builds `` `Layer ${ed.doc.layerCount + 1}` `` in `ui/src/modes/pixel/doc-ops.ts`; Image mode gets `format!("Layer {}", …)` from `pincel-image-core` (`command/layers.rs`).

## Edge cases

| Scenario | Expected behavior |
| -------- | ----------------- |
| Browser languages `fr-FR, de-DE` | German (first German / English entry wins) |
| Browser languages `en-GB, de-DE` | English |
| Stored pref holds an unknown value (e.g. `fr`) | Ignored; browser language used |
| Language switched while a menu or dialog is open | Its labels re-render in the new language |
| Message parameter missing from the call | The `{placeholder}` text stays visible instead of failing |
