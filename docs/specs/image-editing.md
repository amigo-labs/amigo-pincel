# Image-mode editing: layers, tools, compositing, undo

## Summary

> Completed: 2026-10-29

- Image-mode layer stack on `pincel-image-core`: add, delete, duplicate, rename, drag-reorder, opacity, blend mode, visibility and lock, plus Merge Down, Merge Visible and Flatten, each one undo step; a locked layer refuses every pixel edit through the `edited_layer` gate in `pincel-image-wasm`.
- Linear-light compositing with twelve W3C blend modes; Soft Light now follows W3C Compositing-1 instead of the inherited Pegtop formula (Decision Log 2026-10-29).
- The §5.4 tool set: Brush, Eraser, Recolor, Smudge, Paint Bucket, Gradient, Eyedropper, Line, Shapes, Text and the three Move variants, with right-button background color, Shift constraints, selection clipping and one undo step per gesture; Pan and Zoom as rail tools and the shared tool keys.
- Selections (rectangle, ellipse, lasso, polygon, magic wand, combine modes, feather) and the Select menu as undoable steps; Delete, the Image menu canvas transforms and the Layer menu flips / rotations.
- A bounded undo / redo history that drops the redo branch on a new edit and the oldest step once full.

## Context

Image mode is the paint.net-style editor (§1.1) behind PNG / JPEG / WebP / BMP / GIF / TIFF / OpenRaster documents. It runs on its own core, `pincel-image-core`, inherited from the archived sister project `amigo-fineliner` (Decision Log 2026-09-06 "Two cores, one shell"): a dense, canvas-sized layer stack blended in linear light, with a JSON `CommandSpec` wasm ABI. This spec records what that editor does today — the layer stack, the tool set of §5.4, the selection, the Image / Layer / Select menus, compositing and undo — so it can be accepted and kept from regressing.

Already decided: the tool set and keys (§5.4, Decision Log 2026-10-27), the layer lock refusing pixel edits (2026-10-12), pen pressure and tilt (2026-10-12, owned by the `pen-input` spec).

## Scope

### In scope

- The layer stack: add, delete, duplicate, rename, reorder, opacity, blend mode, visibility, lock, Merge Down, Merge Visible, Flatten
- Compositing of the layer stack (visibility, opacity, twelve blend modes, linear-light blending)
- The Image-mode tools of §5.4: Move (three variants), Pan, Zoom, Marquee, Lasso, Magic Wand, Brush, Eraser, Recolor, Smudge, Paint Bucket, Gradient, Eyedropper, Line, Shapes, Text
- The selection: shapes, combine modes, feather, Select menu, Delete, selection bounding every pixel tool
- Image menu (canvas flip / rotate / resize / scale / crop) and Layer menu transforms (flip / rotate)
- Undo / redo of every document edit
- Selection gestures that start on the stage around the canvas, deselecting by click and by Escape (added 2026-10-30)

### Out of scope

- Paste as a new layer — because the `copy-cut-paste` spec owns clipboard editing in both modes, including today's Image-mode paste
- Pen pressure and tilt — because the `pen-input` spec covers them
- Effects and adjustments — because the `effects-adjustments` spec covers them
- Opening, saving and exporting files, image-size limits — because the `image-files` spec covers them
- Layer groups — because the planned `image-layer-groups` spec adds them; Image mode has no groups today
- The shared keymap's non-tool actions, the tool rail layout and the touch modifier toggles — because the `app-shell`, `shortcut-overview` and `tablet-gestures` specs cover them
- Autosave of Image documents — because the `autosave-recovery` spec covers it
- Starting Brush, Eraser, Recolor, Smudge, Paint Bucket, Gradient, Eyedropper, Line, Shapes, Text or a Move variant on the stage — because the owner asked for selection gestures only; opening the stage to other tools is a separate decision (AC-32)

## Acceptance criteria

- [x] AC-01 (always): The composite shows the visible layers bottom to top: a hidden layer contributes nothing, an opaque Normal layer hides everything below it, and a layer's opacity scales its alpha before blending in linear light — a white layer at 50 % opacity over opaque black composites to a gray between 186 and 190, not 128.
- [x] AC-02 (always): Every layer has one of twelve blend modes — Normal, Multiply, Screen, Overlay, Darken, Lighten, Color Dodge, Color Burn, Hard Light, Soft Light, Difference, Exclusion — and composites with the W3C compositing-and-blending formula of that mode (e.g. Multiply with white keeps the backdrop, Screen with black keeps the backdrop, Difference is the absolute difference).
- [x] AC-03 (always): Compositing the same layer stack twice yields identical pixels, and a layer composited source-over never lowers the alpha of the pixels below it.
- [x] AC-04 (event): When the user adds a layer, then a transparent layer appears directly above the active layer and becomes the active layer; one Undo removes it.
- [x] AC-05 (error): If the user tries to delete the only layer, then the document keeps that layer.
- [x] AC-06 (event): When the user renames a layer (Layer ▸ Rename…), drags it to a new position by its grip, duplicates it, or changes its opacity, blend mode, visibility or lock, then the change shows in the layers panel and each is one undo step that restores the previous state; opacity is clamped to 0–100 %, and consecutive opacity changes to the same layer form one undo step.
- [x] AC-07 (state): While a layer is locked, the pixel-writing tools refuse to change it and a notice "Layer “<name>” is locked" appears; the layer can still be renamed, hidden, reordered and unlocked, and after unlocking it accepts paint again.
- [x] AC-08 (event): When the user chooses Merge Down, Merge Visible or Flatten, then: Merge Down combines the active layer into the layer below, which keeps its own blend mode and opacity; Merge Visible merges the visible layers into one without changing the composite and keeps hidden layers; Flatten leaves one fully opaque layer composited over white. Each is one undo step that restores the stack.
- [x] AC-09 (event): When the user drags with the Brush, then a connected stroke is painted on the active layer in the foreground color with the chosen size, opacity, hardness and tip (a soft tip's edge is lighter than its center; 50 % opacity over transparency yields half alpha), and the whole drag is one undo step.
- [x] AC-10 (event): When the user paints with the Brush or the Paint Bucket using the right mouse button, then the background color is used; when the user clicks with the Eyedropper using the right mouse button, then the sampled color becomes the background color.
- [x] AC-11 (state): While a selection exists, the Brush, Paint Bucket, Gradient, Shapes, Line and Text change only pixels inside it, and Delete reduces a partially selected pixel's alpha in proportion to its selection coverage.
- [x] AC-12 (event): When the user erases, then in "to transparent" mode the erased pixels lose alpha by the eraser's opacity (50 % opacity halves an opaque pixel's alpha), and in "to background" mode they take the background color; the stroke is one undo step.
- [x] AC-13 (event): When the user clicks with the Paint Bucket, then the pixels matching the clicked color within the tolerance are filled — only the connected region when Contiguous is on, every matching pixel when off — sampling either the active layer or the composite of all layers; one undo step.
- [x] AC-14 (event): When the user drags with the Gradient tool, then the active layer gets a ramp from the foreground (at the drag start) to the background color (at the drag end): Linear keeps the end color past the drag end, Reflected mirrors through the start, Radial is symmetric around the start; in the Transparency channel the existing colors stay and only their alpha ramps. One undo step.
- [x] AC-15 (event): When the user drags with Recolor, then only pixels within the tolerance of the background color under the tip are repainted with the foreground color, other pixels stay unchanged, and a stroke delivered in several segments gives the same result as one delivered at once.
- [x] AC-16 (event): When the user drags with Smudge, then the color under the tip is carried along the stroke — further with higher strength; strength 0 and a flat single-color area change nothing; a stroke delivered in segments gives the same result as one delivered at once.
- [x] AC-17 (event): When the user drags with Line, Rectangle, Rounded Rectangle, Ellipse or Polygon, then the shape is drawn on the active layer as outline (foreground color), fill (background color) or both, with the stroke width, dash pattern (solid / dashed / dotted) and anti-alias setting; a line is stroked whatever the fill mode; one undo step.
- [x] AC-18 (event): When the user holds Shift while dragging a shape or a line, then an area shape's box becomes a square and a line snaps to the nearest multiple of 45°.
- [x] AC-19 (event): When the user commits text with the Text tool, then it is rasterised onto the active layer in the foreground color at the clicked point, a larger size covers more pixels, and the commit is one undo step; empty text changes nothing.
- [x] AC-20 (event): When the user clicks with the Eyedropper, then the foreground color becomes the average of a 1, 3, 5, 11 or 31 px square around the point, taken from the active layer or from the composite; a click off the canvas changes nothing.
- [x] AC-21 (event): When the user drags with a Move variant, then Move Layer shifts the active layer's pixels (pixels pushed past the canvas edge are lost, the vacated area becomes transparent); Move Selected Pixels lifts only the selected pixels, leaves transparency behind, composites them over what lies at the target and takes the outline along, so a second drag carries them further; Move Selection moves only the outline. Each drag is one undo step.
- [x] AC-22 (event): When the user makes a selection with Rectangle Select, Ellipse Select, Lasso, Polygonal Lasso or Magic Wand, then the selection covers that shape (the wand: the pixels within the tolerance of the clicked color, contiguous or global, from the layer or the composite); a feather radius gives partial coverage at the edges and keeps the deep interior fully selected; Add, Subtract and Intersect combine the new shape with the existing selection as union, difference and overlap.
- [x] AC-23 (event): When the user chooses Select All, Deselect, Invert Selection, or Expand / Contract / Feather (which ask for a radius in px), then the selection changes accordingly and each change is one undo step.
- [x] AC-24 (event): When the user presses Delete, then the selected pixels of the active layer become transparent, or the whole layer when nothing is selected; one undo step.
- [x] AC-25 (event): When the user flips or rotates the canvas, resizes the canvas with an anchor, scales the image, crops to the selection, or flips / rotates the active layer, then: canvas flips and rotations transform every layer and a 90° rotation swaps width and height; Resize Canvas keeps the existing pixels at the chosen anchor and crops what falls outside; Scale Image resamples every layer to the new size; Crop shrinks the canvas to the selection's bounding box; layer flips and rotations keep the canvas size. Each is one undo step; Resize and Rotate drop the selection and Undo restores it.
- [x] AC-26 (always): Undo reverts the last document edit and Redo re-applies it; a new edit after an Undo discards the redo steps; the history has a fixed capacity and drops the oldest step once full.
- [x] AC-27 (event): When the user selects the Pan tool (H) or the Zoom tool (Z), then the rail shows it active; a click with Zoom steps the view in, and the zoom-out and 1:1 buttons keep working while Zoom is the active tool.
- [x] AC-28 (event): When the user presses a tool key, then the tool of §5.4 becomes active — V Move (repeated presses cycle Move Layer, Move Selected Pixels, Move Selection), H Pan, Z Zoom, M Marquee, Q Lasso, W Magic Wand, B Brush, E Eraser, R Recolor, S Smudge, G Paint Bucket, N Gradient, I Eyedropper, L Line, U Shapes (repeated presses cycle Rectangle, Rounded Rectangle, Ellipse, Polygon), T Text.
- [ ] AC-29 (event): When a Rectangle Select, Ellipse Select, Lasso or Polygonal Lasso gesture starts on the stage — the part of the editor's canvas area that the canvas does not cover, excluding controls floating over it (zoom control, on-screen modifier toggles) — then it builds the shape it would build if the canvas extended under the pointer, and the selection keeps only that shape's canvas pixels: a Rectangle Select dragged from the stage beyond the canvas's top-left corner to the canvas point (10.4, 6.6) selects the 10 × 7 box at (0, 0) (each corner snaps to its nearest pixel grid line), and a Lasso or Polygonal Lasso traced around the canvas's top-left corner selects pixel (0, 0).
- [ ] AC-30 (event): When Rectangle Select or Ellipse Select is released with a box of zero width or height after snapping (a click), when a Rectangle Select, Ellipse Select, Lasso or Polygonal Lasso gesture or a Magic Wand click whose shape's bounding box lies entirely off the canvas (for example a click on the stage), or when a freehand Lasso drag ends with fewer than three points, then in replace mode a present selection is cleared as one undo step, as Select ▸ Deselect does; with no selection present (Select ▸ Deselect disabled), or in add, subtract or intersect mode, nothing changes and no undo step is added.
- [ ] AC-31 (event): When Escape is pressed (no dialog open, focus not in a text field), then a Rectangle Select, Ellipse Select or Lasso drag or an open Polygonal Lasso is discarded without a selection change or undo step, and moving and releasing the pointer afterwards changes nothing; any other drag in progress is cancelled as before and the selection stays; with no gesture in progress, a present selection is cleared as one undo step.
- [ ] AC-32 (event): When a press with the Brush, Eraser, Recolor, Smudge, Paint Bucket, Gradient, Eyedropper, Line, Shapes, Text or a Move variant starts on the stage, then no pixel changes and no undo step is added; the Pan and Zoom tools, Space-drag and middle-button panning work from the stage as they do from the canvas.

## Technical notes

Hints, verified 2026-10-29; paths and line numbers drift.

**Document model** (`crates/pincel-image-core/src/document/`)

- `Document { id, title, canvas: CanvasSize, layers: Vec<Layer> /* bottom (0) → top */, active_layer, selection: Option<SelectionMask> /* None = everything */, metadata }`; `MAX_LAYERS = 999`; at least one layer always (`DocumentError::LastLayer`).
- `Layer { id: Uuid, name, kind: LayerKind::Raster, pixels: ImageBuffer /* straight-alpha RGBA8, canvas-sized */, opacity: f32 /* 0..=1 */, blend_mode: BlendMode, visible, locked }`.
- `BlendMode`: `Normal, Multiply, Screen, Overlay, Darken, Lighten, ColorDodge, ColorBurn, HardLight, SoftLight, Difference, Exclusion` (no HSL modes, unlike Pixel mode).
- `SelectionMask`: one coverage byte per canvas pixel; `apply_mode(prior, shape, SelectionMode)` combines (Subtract without a prior selection starts from everything).

**Compositing** (`render/mod.rs`): `compose(&[Layer]) -> ImageBuffer` — per pixel, sRGB → linear, W3C blended source `(1-da)·Cs + da·B(Cb,Cs)`, source-over, back to sRGB; skips hidden layers and `opacity <= 0`. `compose_region(layers, Rect)` returns exactly the matching sub-rect (the viewport renderer). `compose_over(layers, Color::WHITE)` is Flatten.

**Undo** (`command/mod.rs`): `CommandBus { document, history }`; `DEFAULT_UNDO_CAPACITY = 100`, `UndoStack::with_capacity` clamps to `10..=500`. Brush-type strokes arrive as one command per pointer event and merge by `stroke_id` (`SetPixels::merge_with`); `SetLayerOpacity` merges consecutive edits on one layer. Selection changes are undoable `SetSelection` commands (unlike Pixel mode).

**wasm** (`crates/pincel-image-wasm/src/lib.rs`, handle-based): `create_document`, `apply_command(handle, json)`, `undo`, `redo`, `set_active_layer`, `pick_color(handle, x, y, sample, size)`, `composite`, `composite_region`, `get_document_info` (`{ width, height, layer_count, active_layer, can_undo, can_redo, undo_depth, has_selection, layers: [{ id, name, opacity, blend_mode, visible, locked }] }`), `get_layer_thumbnail` (32×32), `get_selection_bounds`, `get_selection_mask`, `register_font`. `apply_command` refuses a pixel edit on a locked layer with `"layer is locked"`; `CommandSpec::edited_layer` lists the pixel edits.

`CommandSpec` tags (TS mirror generated into `ui/src/modes/image/core/generated/CommandSpec.ts`): `pencil_stroke`, `recolor_stroke`, `smudge_stroke`, `eraser_stroke`, `fill_bucket`, `translate_layer`, `translate_selection`, `translate_selection_mask`, `delete_selection`, `add_layer`, `remove_layer`, `move_layer`, `duplicate_layer`, `rename_layer`, `set_layer_opacity`, `set_layer_blend_mode`, `set_layer_visible`, `set_layer_locked`, `merge_down`, `merge_visible`, `flatten_image`, `select_rectangle`, `select_ellipse`, `select_polygon`, `select_wand`, `select_all`, `deselect`, `invert_selection`, `expand_selection`, `contract_selection`, `feather_selection`, `transform_layer` (`flip_h` / `flip_v` / `rotate_180`), `rotate_layer_90`, `flip_canvas`, `rotate_canvas` (`cw90` / `ccw90` / `rotate_180`), `scale_image`, `resize_canvas` (anchor), `crop_to_selection`, `draw_shape` (`line` / `rectangle` / `rounded_rectangle` / `ellipse` / `polygon`), `draw_gradient` (kind `linear` / `reflected` / `radial` / `conical` / `diamond`, channel `color` / `transparency`), `draw_text`. A command that misses the canvas, has a zero offset, an empty selection or a bad layer index is a silent no-op (no undo step).

**Stage input** (AC-29 – AC-32): today `attachTools(surface, …)` (`components/canvas/MainCanvas.svelte`) binds the tool dispatcher to the document-sized `surface` div, so a press on the stage around it is lost; the viewport div only handles Pan, Zoom, Space, middle button and pinch. `toCanvasPoint()` (`tools/pointer.ts`) already maps any client point relative to the surface rect, unclamped, and `pincel-image-core` clips every selection shape to the canvas. The viewport also hosts the zoom control and the text entry, which keep their own pointer input. Escape today only calls `gestureControl.cancel()`; a click without drag commits nothing (`w`/`h` = 0). AC-30's deselect is the `deselect` command, sent only while a selection is present.

**UI** (`ui/src/modes/image/`): `ImageEditor.svelte` (menus, keys, dialogs), `core/controller.ts` (builds every command; Gradient: `from` = foreground, `to` = background; Recolor: `from` = background, `to` = foreground; shapes: stroke = foreground, fill = background, both at the tool opacity), `tools/pointer.ts` (Shift = add, Alt = subtract, Shift+Alt = intersect for selections; Shift constrains shapes; right button → background color), `components/panels/LayersPanel.svelte` over the shared `lib/components/layers/LayersPanel.svelte`. Text uses the bundled Liberation Sans, registered once (`ensureFont`).

## Edge cases

| Scenario | Expected behavior |
| -------- | ----------------- |
| A stroke, shape or fill entirely off the canvas | Nothing changes, no undo step |
| Move by a zero offset | Nothing changes, no undo step |
| Move Selected Pixels with no selection | Moves the whole layer |
| Move Selected Pixels with an empty selection | Nothing changes |
| Merge Down on the bottom layer | Refused; the menu item is disabled |
| Merge Visible with every layer hidden | Nothing changes |
| Crop to Selection without a selection | Nothing changes; the menu item is disabled |
| Invert Selection with no selection | Results in an empty selection (no selection means everything is selected) |
| Expand / Contract / Feather with no selection | Nothing changes |
| Magic Wand click off the canvas | See AC-30: replace mode clears a present selection, other modes change nothing |
| Selection gesture entirely on the stage, never touching the canvas | As AC-30: replace mode clears a present selection (one undo step), other modes change nothing |
| Canvas zoomed so far that it covers the whole viewport | There is no stage; gestures start on the canvas as before |
| Stage gesture released outside the window | The release still ends it (pointer capture) |
| `pointercancel` (touch, pen) during a stage gesture | The gesture is abandoned; the selection stays |
| Right button pressed on the stage with a selection tool | Nothing happens |
| Text entry open, press on the stage | The entry commits, as a press anywhere outside it does today |
| Polygonal Lasso vertices placed on the stage | Allowed; the closed polygon is clipped to the canvas — requiring on-canvas vertices would bring the edge problem back |
| Gradient with a zero-length drag | Nothing changes |
| Text with only whitespace, or the font cannot be loaded | Nothing is committed, no error |
| Adding a layer to a document with 999 layers | Refused |
| Expand Selection with a huge radius | Selects everything without overflow |

## Decisions

- AC-10, AC-18 and AC-28 were green on their first run: the behavior already existed, the spec records it. To show the new AC-10 and AC-18 tests are not vacuous they were run red against a temporarily mutated `ui/src/modes/image/tools/pointer.ts` (right button forced to the foreground color; Shift constraint, then only the 45° line snap, disabled; Eyedropper right click sampling into the foreground) and failed on the expected assertions; the mutation was reverted.
- The new e2e tests read the document through the Eyedropper (a 1 px composite sample lands in the foreground swatch), because tests stay on the DOM and app code never reads canvas pixels (AGENTS.md §7.4, §9).
- AC-28's G is asserted against the rail label "Fill", the Paint Bucket's name in the Image-mode tool rail.
- The evidence gaps found by the first `/spec-check` (AC-04, AC-06, AC-07, AC-17, AC-19, AC-20, AC-23) were closed with tests that were green on their first run, since the behavior existed. Each was run red against a temporary, reverted break. Core: `AddLayer::above` inserting one slot higher; shape anti-alias forced off; stroke width pinned to 2; text color forced to black, then text x offset by 20 px; the 5, 31, then 11 px sample edges shrunk. Wasm: `MoveLayer` counted as a pixel edit; Select All recorded as two steps. UI: Duplicate, opacity, blend mode and visibility handlers no-op'd one at a time; Feather's Apply no-op'd; the Brush made a no-op after the lock check.
- The locked-layer e2e now proves both directions with Undo, not with `undo.isEnabled()`: after the refused stroke, Undo reverts the lock itself (no step was recorded); after unlocking, Undo reverts the stroke and leaves the layer unlocked. Its lock / unlock locators use exact names, because role names match case-insensitively by substring and "Unlock X" contains "lock X".
- The second `/spec-check` found Image-mode Soft Light used the Pegtop formula, not the W3C formula AC-02 names. This was fixed as a bug (Decision Log 2026-10-29, `pincel.md` §15): `soft_light_matches_absolute_w3c_values` was red before the fix (cb 0.25, cs 1 gave 0.4375, not 0.5). Only the `cs > 0.5` branch changed; the compose snapshots and proptests do not use Soft Light and stayed unchanged.
- The other tests from that round were green on their first run. Each was run red against a temporary, reverted break. AC-02: Overlay's operands swapped, then Hard Light's. AC-07: `FillBucket` dropped from `CommandSpec::edited_layer`; the test now names every pixel-writing variant, one line each. AC-21: Move Selection shifting by `(dx, 0)`. AC-23: Invert Selection recorded as two steps.
- AC-07's hide and reorder of a locked layer is evidenced in `pincel-image-wasm` through `run_command` behind the `edited_layer` gate, because `apply_command` itself builds a `JsError` and so only runs on wasm targets.
- 2026-10-30: Revision — selection gestures may start on the stage around the canvas (AC-29 – AC-32), and Image mode deselects in replace mode as Pixel mode does: by a click without drag, by a gesture off the canvas, and by Escape with no gesture in progress. Requested by the owner (edge pixels were hard to hit; Image mode had no click or Escape deselect). Status back to `todo` for the new ACs; AC-01 – AC-28 stay verified because their behavior on the canvas is unchanged — only presses on the stage, clicks without drag, Escape and the Magic Wand edge row are new.
- 2026-10-30: Only the selection gestures, the Magic Wand and view tools start on the stage (AC-32) — because the owner asked for selections; Gradient, Line or Move Selection could work from the stage too, but that is a separate decision.
- 2026-10-30: A selection gesture or wand click whose bounding box lies entirely off the canvas deselects in replace mode and changes nothing in the other modes (AC-30), the same rule as Pixel mode (`pixel-selection-move` AC-22) — because combining an empty shape would empty the selection under intersect, which nobody means by clicking beside the canvas.
- 2026-10-30: Escape and click deselect are specified here rather than in `app-shell` or `shortcut-overview` — because they are selection behavior, not keymap entries.
- 2026-10-30: Deselecting by click or Escape is one undo step, and none when nothing was selected — because Select ▸ Deselect already is one undo step (AC-23) and a click should undo the same way; an empty step would clutter the history.
- 2026-10-30 (spec-build): The viewport takes the tool events and the pointer capture, and has `user-select: none` — because a Brush drag over the selectable viewport started a text selection that the next press dragged away (`dragstart`, then `pointercancel`), which silently dropped the following marquee.
